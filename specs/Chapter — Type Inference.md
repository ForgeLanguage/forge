В Forge типы обычно указываются явно.  
Однако в некоторых случаях язык может вывести тип автоматически.

Это уменьшает количество шаблонного кода, не усложняя понимание программы.

---

# 1. Локальный вывод типов

Тип может быть опущен, если он однозначно определяется из выражения.

```forge
const name = "Forge"
var count = 10
```

Эквивалентно:

```forge
const name: String = "Forge"
var count: Int = 10
```

---

# 2. Правило

> Тип можно опустить, если он полностью определяется из правой части.

---

## Примеры

```forge
const sum = 5 + 3        // Int
const flag = true        // Bool
const text = "Hello"     // String
```

---

## С вызовом функций

```forge
const user = User.new()
```

Тип выводится из возвращаемого значения функции.

---

## С generics

```forge
const value = identity(10)   // T = Int
```

Если тип можно вывести из аргументов — он выводится.

---

# 3. Когда вывод невозможен

Если тип неоднозначен, его нужно указать явно.

---

## `null`

```forge
const value = null      // ❌ ошибка
const value: Int? = null // ✅
```

---

## Пустые коллекции

```forge
const list = []           // ❌ неизвестен тип элементов
const list: Int[] = []    // ✅
```

---

## Неочевидные generics

```forge
const repo = Repository.new()        // ❌
const repo = Repository<User>.new()  // ✅
```

---

# 4. Ограничения

Вывод типов применяется **только к локальным переменным**.

---

## Нельзя

```forge
public name = "Forge"   // ❌
```

---

## Нужно явно

```forge
public name: String = "Forge"
```

---

## Функции

```forge
public add(a: Int, b: Int): Int {
    return a + b
}
```

Типы параметров и возвращаемое значение всегда указываются явно.

---

# 5. Почему не везде

Forge не делает полный вывод типов, потому что это ухудшает читаемость API и делает поведение менее предсказуемым

---

# 6. Философия
- локальный код — можно упростить
- публичный API — должен быть явным
- тип — часть контракта

---

# 7. Итог

- `const x = expr` — допустимо
- `var x = expr` — допустимо
- тип выводится из выражения
- если тип неочевиден — он обязателен
- сигнатуры и поля всегда явные
