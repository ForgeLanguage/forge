# Namespaces, Packages and `use`

По мере роста проекта код начинает разделяться на множество файлов и библиотек.

Forge использует пространства имён, автоматически выводимые из структуры каталогов, и встроенную систему пакетов.

---

# 1. Пространства имён

Каждый файл автоматически принадлежит пространству имён, соответствующему его расположению в проекте.

Например:

```text
src/
 ├─ app/
 │   └─ User.forge
 └─ utils/
     └─ StringUtils.forge
```

Файл:

```text
src/app/User.forge
```

принадлежит пространству имён:

```forge
app
```

`src` является корнем исходников проекта и не входит в пространство имён.
Поэтому `src/app/User.forge` импортируется как:

```forge
use app.User
```

а не как:

```forge
use src.app.User
```

Файл:

```text
src/utils/StringUtils.forge
```

принадлежит пространству имён:

```forge
utils
```

Явно объявлять namespace не требуется.

---

# 2. Директива `use`

Для доступа к типам и функциям из других пространств имён используется директива `use`.

```forge
use utils.StringUtils
```

После этого тип становится доступен по короткому имени:

```forge
const result: String = StringUtils.trim(" test ")
```

Без `use` пришлось бы писать полное имя:

```forge
const result: String = utils.StringUtils.trim(" test ")
```

Полные имена также считаются относительно `src`, а не относительно корня
проекта. Например, `src/app/User.forge` можно использовать как `app.User`, но не
как `src.app.User`.

---

# 3. Импорт нескольких символов

Можно импортировать несколько элементов сразу.

```forge
use app.User
use app.Role
use app.Permission
```

---

# 4. Wildcard imports

Forge не поддерживает wildcard imports.

```forge
use app.* // ошибка
```

Каждый импорт должен явно называть конкретный символ. Это сохраняет читаемость
файла, упрощает диагностику конфликтов и делает зависимости модуля очевидными.

---

# 5. Конфликт имён

Если после импорта возникает неоднозначность:

```forge
use app.User
use legacy.User
```

то короткое имя использовать нельзя:

```forge
const user: User // ❌ ошибка
```

Следует использовать полное имя:

```forge
const user: app.User = app.User.new()
```

или:

```forge
const user: legacy.User = legacy.User.new()
```

---

# 6. Структура проекта

Минимальная структура проекта:

```text
project/
 ├─ src/
 ├─ packages/
 ├─ forge.toml
 └─ forge.lock
```

---

## `src`

Исходный код проекта.

```text
src/
 ├─ app/
 ├─ services/
 └─ utils/
```

---

## `packages`

Локальное хранилище пакетов проекта.

Содержит версии библиотек, используемых данным проектом.

```text
packages/
 ├─ http/
 ├─ json/
 └─ logging/
```

---

# 7. Файл `forge.toml`

Описание проекта и его зависимостей.

Пример:

```toml
entry_point = "./main.forge"
packages_path = "./packages/"

[package]
name = "task-manager"
version = "1.0.0"

[dependencies]
http = "1.2.0"
json = "3.1.0"
```

`entry_point` задаёт файл, который компилируется при запуске компилятора на
директорию проекта или `forge.toml`.

Если ключ отсутствует, используется значение по умолчанию:

```toml
entry_point = "./main.forge"
```

`packages_path` задаёт локальное хранилище пакетов проекта.

Если ключ отсутствует, используется значение по умолчанию:

```toml
packages_path = "./packages/"
```

Каждый локальный пакет внутри `packages_path` должен содержать собственный
`forge.toml` с секцией `[package]`.

Минимальные обязательные поля пакета:

```toml
[package]
name = "http"
version = "1.2.0"
```

Имя пакета должно совпадать с именем каталога пакета.

В проекте с корневым `forge.toml` каждый импортируемый локальный пакет должен
быть объявлен в `[dependencies]`.

```toml
[dependencies]
http = "1.2.0"
```

Версия в `[dependencies]` должна совпадать с версией установленного локального
пакета.

Если `[dependencies]` не пустой, в проекте должен быть `forge.lock`.

`forge.lock` должен фиксировать те же имена пакетов и те же версии, что указаны
в `[dependencies]`.

Первый сегмент `use` для локального пакета является именем пакета, а путь внутри
пакета считается относительно `src` этого пакета.

Например:

```forge
use http.Client
```

разрешается как:

```text
packages/http/src/Client.forge
```

А:

```forge
use http.client.Request
```

разрешается как:

```text
packages/http/src/client/Request.forge
```

# 8. Файл `forge.lock`

Фиксирует точные версии установленных зависимостей.

Пример:

```toml
http = "1.2.0"
json = "3.1.0"
```

Этот файл автоматически создаётся и обновляется инструментарием Forge.

Обычно он хранится в системе контроля версий.

В текущей локальной модели компилятора `forge.lock` проверяется как плоская
TOML-таблица:

```toml
http = "1.2.0"
json = "3.1.0"
```

Каждый ключ должен соответствовать зависимости из `[dependencies]`, а версия
должна совпадать. Лишние записи и отсутствующие зависимости считаются ошибкой.

---

# 9. Глобальное хранилище пакетов

Forge поддерживает глобальный кэш пакетов.

При установке зависимости пакет сначала ищется в локальном хранилище проекта:

```text
project/packages/
```

Если нужной версии нет, используется глобальный кэш:

```text
~/.forge/packages/
```

Если пакет отсутствует и там, он скачивается из репозитория пакетов.

Это позволяет нескольким проектам использовать одну и ту же установленную версию библиотеки.

---

# 10. Версии пакетов

Каждый пакет имеет собственную версию.

```toml
[package]
name = "http"
version = "1.2.5"
```

Кроме версии пакет может указывать минимальную совместимую версию API.

```toml
[package]
name = "http"
version = "1.2.5"
compatible = "1.0.0"
```

Это означает:

- текущая версия пакета — `1.2.5`
    
- пакет гарантирует обратную совместимость начиная с `1.0.0`
    

---

# 11. Публичность и импорт

Директива `use` подчиняется правилам видимости.

Можно импортировать только символы, доступные из текущего пакета.

Например:

```forge
public class User { ... }
```

доступен всем пакетам.

---

```forge
internal class UserRepository { ... }
```

доступен только внутри текущего пакета.

Попытка импортировать недоступный символ приведёт к ошибке компиляции.

---

# 12. Стандартная библиотека

Типы и функции стандартной библиотеки доступны автоматически.

Например:

```forge
String
Int
List<T>
Task<T>
```

Для их использования директива `use` не требуется.
